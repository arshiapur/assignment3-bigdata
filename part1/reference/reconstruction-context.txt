Producer:
- Poll RSS and combine each article's title and summary.
- Strip markup and normalize whitespace.
- Produce JSON with:
  id, text, source, url, published_at, ingested_at.
- Derive a stable article ID from its GUID or URL.
- Use SQLite in a configurable state directory to remember acknowledged IDs.
- Record an ID after Kafka acknowledges delivery.
- Retain articles.jsonl and polls.jsonl for audit evidence.
- An unchanged article must not be counted again on each poll.
- Explain that the initial poll includes existing feed backlog.
- Do not download full article pages unless necessary.

Spark:
- Read JSON from Kafka using Structured Streaming.
- Use startingOffsets=earliest for a new checkpoint.
- Drop duplicate article IDs.
- Extract entities with spaCy, loading the model once per Python worker.
- Suggested labels:
  PERSON, ORG, GPE, LOC, NORP, FAC, EVENT, PRODUCT,
  WORK_OF_ART, LAW, LANGUAGE.
- Exclude dates/times/numeric quantities.
- Case-fold entity text and normalize whitespace.
- Count entity occurrences cumulatively, grouped by entity text and label.
- Use a configurable processing trigger, e.g. 15 seconds.
- Publish complete cumulative count snapshots to a second Kafka topic.
- Include:
  entity, label, count, run_id, batch_id, version,
  snapshot_size, observed_at.
- Use version=batch_id+1.
- Persist Spark checkpoints in a configurable directory.
- Reuse the same checkpoint/run/topics when resuming.
- Use fresh run IDs/topics/directories for independent experiments.
- Explain that unbounded duplicate-ID and aggregation state is suitable for this
  bounded coursework run but requires retention design for production.

Kafka/Elastic:
- Prefer Docker Compose.
- Use host Kafka port 19092 to avoid conflict with a starter broker on 9092.
- Containers connect to kafka:9092.
- Host Python/Spark connects to 127.0.0.1:19092.
- Configure internal/external Kafka advertised listeners correctly.
- Use persistent Docker volumes.
- A new Kafka data volume required ownership 1000:1000 in the previous setup;
  an initialization service handled that.
- Bind host service ports to loopback for this development configuration.
- Elasticsearch and Kibana ports can default to 9200 and 5601.

Logstash:
- Subscribe to output topics such as entity-counts-RUN_ID.
- Set metadata_max_age_ms to 10000 so newly created experiment topics are
  discovered promptly; the default discovery interval delayed short tests.
- Parse Kafka messages as JSON.
- Maintain entities-latest using document ID:
  run_id|entity|label
- Use external_gte versioning with the supplied batch version.
- Also maintain entities-history using document ID:
  run_id|batch_id|entity|label
- Replayed cumulative snapshots must not inflate counts.
- Never sum cumulative snapshots across historical batches.
- Use a persistent Logstash queue/data volume.
- If mounting logstash.yml read-only, put xpack.monitoring.enabled:false in that
  file rather than an environment setting that attempts to rewrite it.

Elasticsearch/Kibana:
- Explicit keyword mappings for entity, label and run_id.
- Long mappings for count, batch_id, version and snapshot_size.
- Date mapping for observed_at.
- Create a Kibana data view.
